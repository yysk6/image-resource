# 开发阶段与验收

状态：阶段 0–4 已实施；阶段 5 验收与交付记录见 [阶段 5 文档](stages/05-delivery.md)。以 [项目规格](SPEC.md) 为行为契约，原题需求见 [项目目标](../项目目标.md)。阶段完成必须记录实际运行结果；未运行或受阻的内容标记为未验证，不能仅因代码存在而判定通过。

实施时阅读对应详细文档：[阶段 0 工程骨架](stages/00-foundation.md) · [阶段 1 模板与身份](stages/01-templates-identity.md) · [阶段 2 素材上传](stages/02-assets.md) · [阶段 3 任务执行](stages/03-tasks.md) · [阶段 4 历史与恢复](stages/04-history.md) · [阶段 5 交付验收](stages/05-delivery.md)。文档中的命令是实施目标；脚本和服务尚未创建时不代表已可执行。

## 阶段 0：工程与交付骨架

**工作**：初始化 `frontend/`、`backend/`，确定并锁定兼容版本；配置 MySQL、迁移、Compose、持久卷和无凭据配置示例；建立 CI 脚本及 README 基础说明。

**完成标准**：干净数据库可通过 Compose 启动并完成迁移；前后端健康响应可访问；容器重启不清空数据库与文件卷；CI 定义在 push/PR 运行规定检查。记录准确启动和检查命令。

## 阶段 1：模板与身份

**工作**：建立演示用户、模板和分类数据及 Java 接口；准备本地封面与来源说明；实现列表、分类筛选、详情、用户切换和基础响应式布局。

**完成标准**：至少两个用户、两个分类及单图/多图模板可通过 API 和页面访问；筛选结果正确；缺失模板、加载中、空数据和请求失败有可理解反馈；切换用户不会保留另一用户的数据。

## 阶段 2：素材上传

**工作**：实现文件存储、素材表、上传和受控预览；完成上传位、预览、替换、移除及前后端校验。

**完成标准**：符合要求图片上传后刷新仍可由服务端读取；错误数量、类型、大小和无效内容被拒绝；上传中或失败无法提交；不同用户不能使用或读取彼此上传的素材。

## 阶段 3：任务受理和后台执行

**工作**：建立任务及素材关系；实现事务提交后调度、有界线程池、三步骤、各阶段延迟与失败注入、状态更新和结果地址；实现单任务查询。

**完成标准**：创建任务返回 202 时模拟任务仍在运行；关闭页面后任务可完成；数据库记录按规定阶段推进并到达终态；每一阶段都可稳定触发失败且后续不执行；拒绝入队时有明确响应及持久失败状态；查询不改变状态；终态不回退。

## 阶段 4：多任务、历史与恢复

**工作**：实现历史接口与页面；接入独立任务轮询、查询失败处理、刷新恢复、用户切换和请求清理。

**完成标准**：连续创建至少两个任务且状态、结果不串扰；刷新后恢复当前用户历史并继续跟踪未完成任务；一个任务结束后停止其轮询，全部结束后没有后台轮询；查询异常保留已有任务且可恢复；切换用户后旧请求无法污染新数据。

## 阶段 5：质量、文档与交付

**工作**：补齐关键自动化测试、界面状态与无障碍细节；执行 CI 与容器全流程；完成 README、资源来源、部署回滚、已知限制及实际 AI 使用说明。

**完成标准**：下列自动化和手工验收通过，或逐条说明未验证与原因；新评估者可按照 README 在容器中复现；报告实际完成情况和边界。

## 自动化验收矩阵

| 编号 | 行为 | 最低验证方式 |
| --- | --- | --- |
| A01 | 素材检查、生成、结果整理严格按顺序运行 | 后端测试记录可观察步骤顺序 |
| A02 | 每一阶段失败时停止后续阶段并保存阶段及原因 | 后端参数化测试覆盖三个失败点 |
| A03 | 成功写入结果，终态不被后续写入或查询改回运行中 | 后端状态测试 |
| A04 | 输入及用户隔离有效，拒绝别人的素材和任务 | 后端接口或集成测试，覆盖正反例 |
| A05 | 执行器拒绝时任务不会无限等待 | 后端测试验证响应和持久状态 |
| A06 | 多任务状态和结果互不覆盖 | 前端组件或状态测试 |
| A07 | 查询异常不等同于任务失败，保留旧状态且可恢复 | 前端测试模拟请求失败及恢复 |
| A08 | 终态停止跟踪，切换用户或卸载后旧请求不污染数据 | 前端测试验证轮询和请求生命周期 |
| A09 | push/PR 执行 lint、类型检查、前端构建、Java 测试与构建 | 检查 CI 配置并实际运行对应命令 |

数据库和文件交互应至少在容器验收中覆盖；有必要时以真实 MySQL 集成测试验证事务和 SQL。测试避免依赖随机失败或真实 AI 服务。

## 手工端到端验收

1. 在干净环境执行 `docker compose up --build`，按照 README 等待服务就绪；检查模板封面和示例图可访问。
2. 用用户 A 按分类浏览并打开单图、多图模板；检查不存在的模板及空、错误状态。
3. 上传合法图片，测试不合法类型、大小、数量以及上传失败、替换、移除；确认提交按钮状态正确。
4. 创建至少两个任务，观察各自等待、阶段变化和成功结果；在任务处理中离开页面并返回。
5. 刷新页面，确认历史来自后端，未完成任务继续更新；完成后确认不再自动查询。
6. 暂停或阻断查询请求，确认展示查询异常而非任务失败；恢复服务或手动恢复查询。
7. 分别配置三个失败阶段和不同耗时，验证失败原因、失败阶段、后续步骤停止及成功场景。以 README 中实际配置方式操作。
8. 切换到用户 B，确认看不到 A 的历史；尝试以 B 查询 A 的任务和素材，应被拒绝。再切回 A 验证历史仍在。
9. 重启容器并检查已完成历史及文件持久化；对于重启时未完成任务，核对 README 中的已知限制，不把恢复执行作为本题验收要求。
10. 按 README 执行前端 lint、类型检查、构建及 Java 测试、构建；核对配置样例、版本、接口、失败演示、回滚和 AI 使用说明。
