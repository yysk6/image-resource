# 阶段 1：模板与演示身份

状态：已实施；完整键盘交互仍需手动验证。前置条件：阶段 0 通过，数据库迁移及前后端联通。契约见 [规格第 3、4.1、4.6 和 6 节](../SPEC.md)。

## 目标与产物

让用户切换演示身份，浏览、筛选模板并进入详情。产出用户和模板迁移/种子数据、Java 接口、模板本地资源、列表和详情页面、必要测试。调用 `frontend-design` 指导页面设计，代码实现使用 `karpathy-guidelines`。

## 实施步骤

1. 新增迁移创建 `demo_user` 和 `template`，定义规格所需字段、主键、非空约束和排序字段。预置至少两位用户、两个分类，模板覆盖单图和多图；将类型、数量、单图大小作为后端返回的真实规则。使用新迁移管理种子，不修改已执行迁移。
2. 准备可离线访问的封面和示例图，确认来源及使用权限；在 README 或资源说明记录来源。通过应用可访问的稳定 URL 提供，容器内路径与数据库中的 URL 一致。
3. 实现 `GET /api/users`、`GET /api/categories`、`GET /api/templates?category=`、`GET /api/templates/{id}`。按 `sort_order` 和确定性次序返回；未知分类返回空列表，未知模板返回 404 和统一错误体。列表数据必须来自后端。
4. 实现演示身份解析：持久化前端选择；统一请求层为相关业务请求附加 `X-Demo-User`；后端校验预置用户存在，非法或缺失身份按规格返回错误。用户列表及公开模板可不要求身份。说明这是可伪造的演示标识，不能用于生产认证。
5. 实现模板列表和分类筛选，包含加载中、无结果、失败与重试；卡片显示标题、分类、封面并可键盘进入详情。详情展示标题、描述、封面和素材规则；不存在模板时展示返回入口。
6. 在全局导航提供当前用户和切换控件。用户切换时清理当前用户相关状态并取消或隔离旧请求；该机制将在后续上传和任务功能中复用。提供窄屏布局、控件标签、焦点样式。

## 验证

- Java 测试覆盖分类筛选、详情存在/不存在、身份有效/无效；验证种子资源 URL 返回可用内容。
- 前端验证分类筛选、空与错误状态、用户切换和键盘导航；不同素材数量模板均显示正确要求。
- 容器中调用列表和详情接口，对照页面；断开接口确认错误提示；检查至少两个屏幕宽度下可操作。
- 执行项目已有前后端相关测试、lint 和类型检查；实际命令及结果写入阶段记录。
