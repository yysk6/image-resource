# 阶段 2：素材上传与管理

状态：实现及验证完成，审查和推送进行中。前置条件：阶段 1 模板及演示用户可用。契约见 [规格第 3、4.2、5、6 节](../SPEC.md)。

## 目标与数据流

图片从浏览器上传至 Java，写入持久卷并记录所属用户；浏览器本地预览仅用于交互，不能作为任务素材。上传完成后获得 `assetId`，阶段 3 创建任务时使用有序 ID 列表。

```text
选择文件 → 本地基础校验 → 本地预览 → POST /api/assets
         → 服务端校验和保存 → 素材记录 → 返回 assetId
```

## 实施步骤

1. 新增 `asset` 表迁移，保存用户、原始名称、服务端相对存储路径、实际 MIME、字节数和创建时间。路径由服务端生成，约束文件放在配置的素材根目录；展示原始名称时安全处理。
2. 定义存储服务：创建目录、以随机文件名写入、读取；写入失败返回可理解错误，避免向数据库保存不可访问的文件。数据库写入失败时尽力清理本次已写文件，清理失败记日志并在限制中说明。
3. 实现 `POST /api/assets`：解析演示身份，multipart 接收图片，限制单次及单文件大小，校验实际文件内容、允许图片格式及声明类型一致性。因为此接口未携带模板 ID，使用系统允许类型和全局大小上限；模板特定数量、格式、大小在阶段 3 创建任务时再次检查。预先设定与所有种子模板兼容的全局上限。
4. 实现 `GET /api/assets/{id}/content`，按用户查询素材并返回图片内容；不存在和无权访问均返回 404。文件读取失败返回可理解错误，不暴露绝对路径。检查请求体大小限制、类型伪造及异常文件路径。
5. 前端按模板所需数量渲染独立上传位；每项维护文件、预览、上传状态、素材 ID 和错误。选择时检查大小、类型；上传失败可重试，成功后可替换或移除。替换或卸载时释放本地 object URL。
6. 用上传代次或取消信号隔离迟到响应：替换、移除、切换用户之后，旧上传结果不得写回当前上传位。预览受控素材时通过带 `X-Demo-User` 的请求取回图片，再管理生成的 object URL。
7. 派生提交就绪条件：所有必填位置上传成功、素材 ID 齐全且无提交进行中；此阶段可先实现状态和交互，真正提交留阶段 3。说明未引用素材不会自动清理。

## 验证

- 后端测试：正常 PNG/JPEG、空文件、伪造 MIME、非图片、过大文件、未知用户、不同用户读取；写入和数据库失败时返回错误且无错误成功记录。
- 前端测试或交互验证：各上传位独立、失败重试、替换、移除、object URL 释放，以及旧请求迟到不覆盖新选择。
- 容器中上传后刷新并读取图片，重启后端容器再次读取，确认文件卷持久化；检查越权访问为 404。
- 运行相关前后端测试和静态检查；记录实际命令及结果。
