# 素材制作网站项目规格

状态：实施基线；2026-11-01。依据：[项目目标](../项目目标.md)。本文描述计划，不代表功能已经实现。原题及用户后续明确要求优先于本文；实现过程中若调整契约，应同步更新本文和相关验收项。

## 1. 目标与范围

构建可独立运行的网站：用户浏览模板、上传图片、提交制作任务，Java 后台顺序执行模拟步骤；用户可以继续浏览、创建多个任务，并在刷新后查看自己的任务及结果。

必须覆盖原题 R-01～R-13；R-14 的 Docker Compose 为本项目交付目标。结果生成使用本地图片和可控延迟，不接入真实 AI。支持桌面与可操作的小屏布局。

不实现真实 AI、支付、模板管理后台、会员、第三方登录、任务自动重试、断点续跑、集群或服务重启后自动恢复。演示身份不提供真实账户安全性。可在 README 讨论后续演进，但不得将未实现能力写成已完成。

## 2. 技术和部署决策

| 层次 | 决策 |
| --- | --- |
| 前端 | Next.js App Router、React、TypeScript；Tailwind CSS；TanStack Query 负责服务端状态及轮询 |
| 后端 | Java 21、Spring Boot 3.5.x、Spring Web、Bean Validation、MyBatis Spring Boot Starter 3.0.x、Maven |
| 数据与文件 | MySQL 8.0；Flyway 管理结构和种子数据；本地文件及 Docker 数据卷保存上传素材和结果 |
| 后台执行 | 单个 Java 实例内的有界 `ThreadPoolTaskExecutor`；独立步骤顺序执行 |
| 查询 | HTTP 轮询；按用户和任务隔离缓存，只跟踪非终态任务 |
| 测试 | JUnit 5、Mockito；Vitest、React Testing Library；必要时使用 MySQL 容器集成测试 |
| 工程 | Docker Compose、GitHub Actions；npm 锁文件、Maven Wrapper 或明确 Maven 版本 |

初始化时选定具体补丁版本，并在依赖文件、锁文件、容器、CI 和 README 中保持一致，实际验证兼容性。MyBatis Starter 3.0 适配 Spring Boot 3.2–3.5、Java 17+；参见 [MyBatis 官方兼容表](https://mybatis.org/spring-boot-starter/mybatis-spring-boot-autoconfigure/)。Node 版本必须满足所选 Next.js 要求，参见 [Next.js 安装文档](https://nextjs.org/docs/app/getting-started/installation)。

本阶段不部署 Redis、消息队列、对象存储或 WebSocket；单实例和轮询足以覆盖验收。线程池与队列有限，饱和时要明确拒绝并保存可理解的失败状态。应用重启可能遗留 `PENDING` 或 `RUNNING` 记录，不承诺自动恢复，README 应解释该限制和人工处理方式。

## 3. 身份与隔离

预置至少两个演示用户；界面提供可见的用户切换入口。前端保存当前选择，并在业务请求中通过 `X-Demo-User` 传递预置用户标识；后端校验该用户存在，并从请求上下文统一取得身份。该标识可伪造，仅供本地演示，不能宣称为认证或安全边界。

素材上传时关联用户；创建任务时校验素材归属。任务详情和历史查询必须按当前用户过滤；访问其他用户的任务时返回 404。上传素材的预览访问同样须校验归属，可由受身份检查的 API 返回文件并由前端以带请求头的方式加载，或设计等效的可验证方案。演示结果可以使用公开静态示例图，但历史记录与任务详情必须隔离。README 说明切换和局限。

切换用户时取消或隔离旧请求、清理当前用户相关状态；旧响应不得覆盖新用户界面。刷新后恢复所选用户和其后端记录。

## 4. 功能需求

### 4.1 模板

- 后端提供分类、模板列表和详情；列表支持分类筛选，数据由数据库种子或后端读取的种子文件提供，不依赖前端硬编码。
- 至少准备两个分类和覆盖单图、多图要求的模板；每项包含 ID、标题、分类、描述、可访问封面、必需图片数、允许 MIME 类型和单图大小上限。
- 封面及结果必须是项目内可用的示例文件或合法可用资源，不依赖付费或内部服务。记录来源与授权情况。
- 列表和详情提供加载、空数据、失败、模板不存在反馈；分类筛选及导航可通过键盘操作。

### 4.2 素材上传

- 根据模板要求渲染上传位；支持选择、预览、替换、移除，每个上传位独立显示上传中、成功或失败，可重试。
- 浏览器校验数量、声明类型和大小；服务端独立校验接收文件的大小与实际内容、允许类型，并生成服务端文件名，不使用用户提供的路径。
- 文件写入持久目录并保存素材记录，上传成功后返回素材 ID；浏览器临时 URL 仅用于本地预览，不能作为后台素材。
- 上传未完成、素材数量不满足要求或提交请求进行中时禁止提交。上传失败不得被当作准备完成。
- 创建任务时重新检查模板要求、素材存在性、文件可用性和用户归属。允许替换或移除后留下未引用素材；本次不要求自动清理，README 写明限制。

### 4.3 任务受理

- `POST /api/tasks` 检查模板、素材及数量等参数，写入任务和素材关系后返回 `202`、任务 ID 与初始状态，不等待制作完成。
- 用户可连续创建多个任务；关闭或离开页面不会取消服务端任务。多任务可排队或并行。
- 数据库事务提交后才调度执行，避免工作线程读到未提交数据。若执行器拒绝入队，受理流程须把任务持久化为 `FAILED` 并写明系统繁忙；响应应明确表示未成功受理，避免永久等待。事务提交与调度之间的进程崩溃窗口仍受重启恢复限制。
- 不要求跨请求幂等；前端在单次提交进行中禁用重复操作。超时后用户重试可能创建重复任务，README 明示。

### 4.4 异步处理

按顺序执行 `MATERIAL_CHECK`（素材检查）、`GENERATING`（模拟生成）、`FINALIZING`（结果整理）。每步具有独立 Java 执行边界，开始时持久化阶段；通过配置提供各阶段延迟和指定失败阶段，结果应可重复。失败后停止后续步骤，记录失败阶段和可理解原因。成功后保存真实可访问的结果图片地址；可复制或引用项目内示例图片，无需实际合成。

整体状态为 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`。允许 `PENDING → RUNNING → SUCCEEDED/FAILED`，入队拒绝允许 `PENDING → FAILED`。终态不可回退；状态更新应限定允许的前置状态，避免迟到写入覆盖终态。每次数据库状态更新使用短事务，延迟期间不持有数据库事务或连接。

查询只读数据库，不推动步骤或通过前端计时制造进度。每个任务记录当前阶段、状态、结果或失败原因及时间。应用关闭页面不影响执行；后端进程停止不保证任务完成或重启恢复。

### 4.5 任务查询与历史

- 查询接口展示当前用户的任务、创建时间、状态、当前阶段、成功结果或失败原因；历史按创建时间倒序。
- 前端请求异常与任务 `FAILED` 分离：保留已知任务数据，标明查询暂不可用并提供恢复查询。
- 每个任务独立维护数据与请求状态；页面刷新从后端恢复历史，并自动跟踪 `PENDING`、`RUNNING` 任务。
- 仅未完成任务自动轮询，任务终态停止其轮询；无未完成任务时不继续轮询。卸载页面、切换用户时清理计时器和请求；防止过期响应覆盖当前数据。
- 成功结果可预览；不要求下载、删除或重新制作。

### 4.6 界面与可访问性

页面包括模板列表、模板详情与制作、历史记录；参考原题附图的主要布局而非逐像素复刻。清晰展示信息层次和加载、空、错误、成功状态。小屏可完成主要流程。按钮使用正确语义，上传控件和图标按钮有可理解标签；保留焦点、键盘操作和基本颜色对比。

## 5. 数据模型

使用 MySQL，时间统一保存 UTC 并在接口使用带时区的 ISO 8601，界面按本地时区展示。主键可用数据库生成的长整型，JSON 中以字符串返回，避免 JavaScript 精度问题。

| 表 | 核心字段 | 约束 |
| --- | --- | --- |
| `demo_user` | `id`, `display_name`, `created_at` | 预置至少两个用户 |
| `template` | `id`, `title`, `category`, `description`, `cover_url`, `required_image_count`, `accepted_mime_types`, `max_file_size_bytes`, `sort_order` | 模板素材规则非空 |
| `asset` | `id`, `user_id`, `original_name`, `storage_path`, `mime_type`, `size_bytes`, `created_at` | 关联用户；存储路径不作为公开输入 |
| `creation_task` | `id`, `user_id`, `template_id`, `status`, `current_stage`, `result_url`, `failure_reason`, `created_at`, `started_at`, `finished_at`, `updated_at` | 用户和创建时间索引；终态字段一致 |
| `task_asset` | `task_id`, `asset_id`, `position` | 同一任务位置唯一；关联任务与素材 |

迁移脚本创建表、索引和演示数据；本地示例文件与种子 URL 保持一致。建表与初始化应在新数据库可重复部署，已存在数据的启动不应被清空。

## 6. API 契约

所有路径以 `/api` 开头，任务和素材接口携带 `X-Demo-User`。接口字段和错误格式最终以实现与 README 一致为准；以下为实施基线。

| 方法与路径 | 作用 | 主要输入 / 输出 |
| --- | --- | --- |
| `GET /users` | 列出演示用户 | 返回 ID、显示名 |
| `GET /categories` | 查询分类 | 返回分类列表 |
| `GET /templates?category=` | 查询模板 | 分类可选；返回卡片与素材要求 |
| `GET /templates/{id}` | 查询详情 | 不存在返回 404 |
| `POST /assets` | 上传一张图片 | multipart `file`；返回素材 ID、类型、大小和预览入口 |
| `GET /assets/{id}/content` | 预览上传素材 | 检查用户归属并返回图片 |
| `POST /tasks` | 受理任务 | `templateId`、有序 `assetIds`；成功返回 202 和任务 ID、状态 |
| `GET /tasks/{id}` | 查询任务 | 返回状态、阶段、结果、失败原因和时间；越权返回 404 |
| `GET /tasks` | 查询个人历史 | 按当前用户过滤并倒序返回 |

统一错误体至少包含稳定的 `code` 和可读 `message`。参数错误返回 400，未知演示用户返回 401，资源不存在或不属于当前用户返回 404，执行器饱和可返回 503。服务端不泄露磁盘绝对路径或堆栈。正式项目中身份机制和 HTTP 状态可随认证方案调整。
